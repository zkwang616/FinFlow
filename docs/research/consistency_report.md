# LLM 金融分析流水线的结论一致性研究

**研究问题**：相同输入、相同流程下，LLM 金融分析流水线重复生成的结论有多稳定？它会不会每次给出不同的理由，甚至方向相反的判断？

**一句话发现**：事实性信息（公司优势、催化剂）相对稳定，但**判断性输出**——风险点、估值区间、投资结论方向——存在显著随机性：10 次重复实验中，投资结论方向在"积极"与"中性"之间 50/50 摇摆，合理估值区间 IoU 仅 0.30。**更关键的是，将采样温度降为 0（贪心解码）后，结论方向依然是 50/50——随机性并不主要来自采样参数，而是模型本身。**

---

## 1. 动机与背景

LLM 正在被用于金融分析：自动研报、投资建议、风险评估。但这类应用的可靠性存在一个很少被检验的问题：**LLM 输出的随机性**。同一个问题、同一份数据，模型可能给出不同答案——这在金融场景中是严重的：一份看多的报告和一份中性的报告，会导向完全不同的决策。

FinFlow 是一个自研的可观测 LLM 金融分析流水线（基于 PocketFlow，4 个角色 agent 并行分析，详见 [DESIGN.md](../DESIGN.md)）。它的可观测层记录每次执行的完整输出，这为"系统性测量结论稳定性"提供了天然实验平台。本研究用该平台回答：**LLM 金融分析的结论有多稳定？**

## 2. 实验设计

### 2.1 数据与流程

- **输入**：AAPL 固定 mock 数据快照（含 4 年财务报表、市场指标、同业估值、3 条新闻），数据日期 2026-08-14，10 次运行完全一致
- **流水线**：数据获取 → 数据处理 → 4 个 agent 并行分析（company overview / valuation / risks / takeaways）→ 报告生成
- **LLM**：DeepSeek（deepseek-chat），`temperature=0.3`（生产常见配置），关闭缓存
- **样本量**：N = 10 次独立运行，共 40 次 agent 调用
- **对照组**：相同设置下以 `temperature=0`（贪心解码）再运行 N=10 次，共 40 次调用，用于分离"采样参数"与"模型本身"对稳定性的贡献

### 2.2 一致性指标

| 指标 | 定义 | 衡量对象 |
|---|---|---|
| 文本相似度 | 全部两两输出的字符 3-gram Jaccard 相似度均值（0-1） | 主文本段落 |
| 列表重叠率 | 两个列表的语义重叠率（贪心 n-gram 匹配，阈值 0.35） | 优势/风险/催化剂等列表 |
| 区间 IoU | 估值区间的交并比 | fair value range 数值区间 |
| 离散字段分布 | 取值分布与信息熵 | risk_rating、结论方向 |
| 方向一致性 | 关键词规则判断结论看涨/看跌/中性 | investment conclusion |

## 3. 结果

### 3.1 总览

| Agent | 主文本相似度 | 关键列表重叠率 | 离散字段 |
|---|---|---|---|
| Company Overview | 0.544 | strengths 0.676 / challenges 0.392 | — |
| Valuation | 0.419 | — | 估值区间 IoU **0.297** |
| Risks | 0.404 | risks **0.373** | risk_rating：Moderate 10/10（稳定） |
| Takeaways | 0.428 | catalysts 0.711 / watch **0.350** | 结论方向：positive 5 / neutral 5（熵 1.0） |
| **整体** | **0.449** | 列表均值 ≈ 0.50 | — |

### 3.1b 温度对照（temperature=0.3 vs 0）

| 指标 | t=0.3 | t=0 | Δ |
|---|---|---|---|
| 整体文本相似度 | 0.449 | **0.689** | +0.24 |
| Company Overview 文本 | 0.544 | 0.837 | +0.29 |
| Valuation 文本 | 0.419 | 0.651 | +0.23 |
| **Risks 文本** | 0.404 | **0.408** | +0.004（几乎不变） |
| Takeaways 文本 | 0.428 | 0.861 | +0.43 |
| risks 列表重叠 | 0.373 | 0.578 | +0.20 |
| catalysts 重叠 | 0.711 | 1.000 | +0.29 |
| watch_indicators 重叠 | 0.350 | 0.811 | +0.46 |
| 估值区间 IoU | 0.297 | 0.477 | +0.18 |
| 风险评级 | Moderate 10/10 | Moderate 10/10 | 稳定 |
| **结论方向分布** | **positive 5 / neutral 5** | **positive 5 / neutral 5** | **无变化（熵 1.0）** |

### 3.2 关键发现

**发现 1：表述层面高度不稳定。** 相同输入下，所有 agent 的主文本平均相似度仅 0.45（1.0 为完全一致）。每次生成的段落结构、措辞、强调点均不同。

**发现 2：判断性内容比事实性内容更不稳定。** 一个清晰的模式：

- 事实/肯定性信息：key_strengths 重叠 0.68、key_catalysts 重叠 0.71（相对稳定）
- 判断/否定性信息：risks 重叠 0.37、key_challenges 重叠 0.39、watch_indicators 重叠 0.35（显著不稳定）

模型对"这家公司好在哪"的表述趋同，但对"该担心什么、该盯什么指标"每次给出不同的答案。

**发现 3：合理估值区间显著摇摆。** 10 次运行全部解析出估值区间，但两两 IoU 均值仅 0.30。实际区间从 $210-$240（"fairly valued"）到 $230-$270（"compelling case"）不等；run 4 甚至使用了不同的估值方法论（同业平均 EV/EBITDA 得 $296 极端值，随后折中）。**同样的数据可以支撑 "fairly valued" 和 "attractive upside" 两种结论。**

**发现 4：投资结论方向存在 50/50 随机波动。** takeaways 的 conclusion 在 10 次中 5 次判定为积极、5 次中性（信息熵 1.0）。风险评级（Moderate）是唯一完全稳定的判断字段——但一个永远"中性"的评级本身也说明该字段的信息量有限。

**发现 5（对照实验）：结论方向的随机性不来自采样温度。** temperature=0 是贪心解码，理论上输出应接近确定性；但结论方向分布仍是 positive 5 / neutral 5（熵 1.0），与 temperature=0.3 完全一致。这意味着方向性结论的摇摆不是采样噪声，而是**模型对"这个标的该给什么方向"本身就无法稳定表达**——即使用确定性最高的解码方式。

**发现 6（对照实验）：不同输出维度对温度敏感度不同。** 温度降低大幅提升了 overview（+0.29）和 takeaways（+0.43）的文本一致性，但 Risks 文本几乎不变（0.404→0.408）——风险文本的多样性是模型内在的，与温度无关。降低温度能"修复"部分维度，但无法修复全部。

## 4. 案例展示（真实输出）

### 4.1 估值区间（前 4 次运行）

| Run | Fair Value Range | 判断 |
|---|---|---|
| 1 | $220-$270 | 与分析师目标一致 |
| 2 | $210-$240 | **"fairly valued"** |
| 3 | $210-$250 | 下沿折价、上沿对齐目标 |
| 4 | $230-$270（内部出现过 $296） | "compelling case" |

### 4.2 风险点（Run 1 vs Run 3）

Run 1 列出的五个风险：iPhone 依赖、竞争、监管、供应链、**高估值（P/E 33.5）**。

Run 3 的五个风险：iPhone 依赖、竞争、监管、供应链、**高估值与市场预期**。

主题重合，但 Run 1 强调"估值导致股价波动"，Run 3 强调"预期落空风险"；Run 4 又把"App Store 监管冲击服务收入"提到第二优先——**风险排序与表述每次不同**。

## 5. 讨论

### 5.1 为什么重要

本研究给出一个反直觉但可复现的证据：**LLM 金融分析的"结论"中，事实性信息尚可依赖，判断性信息（风险、估值、方向）具有显著随机性；且这种随机性不随 temperature=0 消失——方向性判断的不稳定性是模型层面的。** 这直接影响两个下游场景：

1. **投资决策**：同一标的、同一数据，系统既可能输出"fairly valued"也可能输出"upside potential"——如果用户只看一次输出，结论可能取决于"运气"。
2. **策略评估**（与本人在 TradingAgents 修复 look-ahead bias 的工作直接相关）：如果 LLM 分析输出本身不稳定，基于单次输出评估策略绩效会引入噪声；与数据泄漏一样，这是"评估结果不可信"的另一来源。**可复现性不止要求流程可复现，还要求输出可复现。**

### 5.2 局限

- 样本：单一 ticker、N=10、mock 数据（真实市场数据的噪声可能更大或更小）
- 指标：n-gram 相似度是语义的粗略近似；结论方向用关键词规则判断，未做人工标注验证
- 参数：仅对比 temperature ∈ {0, 0.3}，未探索中间值

### 5.3 下一步

1. 多 ticker 扩展：检验"事实稳定、判断随机"是否跨标的成立
2. 方向标注升级：LLM-as-judge + 人工抽样验证，替代关键词规则，排除规则误判可能
3. 模型间对比：同一实验在不同 LLM 上运行，检验方向随机性是否模型特有
4. 报告稳定性可视化：在 FinFlow 前端展示同任务多次运行的结论分布（研究工具化）
5. 缓解方案评估：多数投票 / 多次采样取众数对方向一致性的提升

## 6. 复现

```powershell
# 1. 运行实验（主实验 t=0.3，约 1 分钟，40 次 LLM 调用）
.venv\Scripts\python.exe -m backend.experiments.consistency --ticker AAPL --runs 10

# 2. 对照实验（t=0，40 次 LLM 调用）
.venv\Scripts\python.exe -m backend.experiments.consistency --ticker AAPL --runs 10 --temperature 0.0

# 3. 查看关键字段的跨 run 示例
.venv\Scripts\python.exe -m backend.experiments.show_examples data\experiments\AAPL_<时间戳>\runs.jsonl

# 4. 从已有数据重算指标（不消耗 LLM）
.venv\Scripts\python.exe -m backend.experiments.consistency --from-jsonl data\experiments\AAPL_<时间戳>\runs.jsonl
```

原始数据：`data/experiments/AAPL_20260815_202628/runs.jsonl`（t=0.3）与 `data/experiments/AAPL_20260815_203411/runs.jsonl`（t=0）

## 7. 结论

LLM 金融分析流水线的输出稳定性呈现不对称分布：**事实稳定，判断随机；且判断的随机性不随贪心解码消失**。这一发现既是对 LLM 金融应用可靠性的警示，也指明了改进方向——输出一致性应作为 LLM 金融系统评估的必要维度，与流程可复现性同等重要；在方向性结论依赖单一采样结果前，应引入多次采样/多数投票等缓解机制。
